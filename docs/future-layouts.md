# 相册自由编排：后续迭代

## 目前已经实现

相册编辑器已经从折叠表单升级为“照片库、画布、属性面板”三栏式工作台：

- 多张照片一次上传，再拖进可见画布。
- 照片块、文字块和留白块可以穿插并拖动排序。
- 照片块支持一至三张、主次比例、收窄/常规/通栏宽度、间距和画面比例。
- 文字块支持内容、字号、宽度、对齐与上下留白。
- 桌面、平板和手机三档画布预览。
- 保存草稿后可打开正式网页样式预览；编辑画布不再放置虚构标题或说明文字。

它仍然保存结构化内容，而不是自由坐标或任意 HTML/CSS，因此正式页面在手机上
仍能自然回落，图片也能继续由 Astro 做响应式处理。

## 下一轮候选能力

1. Room 式“画册总览”：降低单张照片在编辑器里的占屏比例，一屏同时看见多组
   图片、节奏与留白，再进入局部编辑。
2. `masonry`：保留原始比例的瀑布流。
3. `textImage`：文字和照片在同一个块内并排。
4. `customGrid`：有限的列宽、跨列与行高控制。
5. 相册级主题：背景、文字明暗、内容宽度和章节色彩。
6. 可复用版式预设：把满意的照片组合保存为模板。
7. 更细的插入反馈：拖到两个块之间时显示明确的落点指示线。

## 实现原则

- 继续使用可验证的布局块联合类型；新增类型只增加新的数据分支和渲染组件。
- 已有照片、文字和留白内容不需要因为新布局类型而迁移。
- 编辑器提供预览与有限参数，不让内容直接保存任意 HTML/CSS。
- 每个新块必须定义移动端回落、响应式图片尺寸和无障碍阅读顺序。
- 图片的替代文字、说明和焦点属于照片库；布局只保存照片 ID 和呈现参数。
- 不做自由坐标和无限画布。它们看起来像 PS，但很难同时保证手机适配、阅读顺序
  和稳定发布；只有真实使用证明结构化画布仍不够时再评估。

## 从山西 06 得到的照片尺寸编排规则

这是一套已在一组横、竖比例混杂的建筑照片中验证过的判断顺序。它优先保护照片之间
的观看关系，不把“填满空白”当成目标。

1. **先确定组，再确定尺寸。** 先判断哪些照片是在共同描述一个场景、动作或结构，再
   决定它们是否应该同排。不要因为照片数量刚好是二、三或四张，就强行拼成一个方格。
2. **默认保留原始比例。** 不为凑齐格子裁切画面。横图应得到更宽的空间，竖图应得到
   更窄的空间；裁切只在作者明确指定时使用。
3. **同排要共享视觉高度，而不是平均列宽。** 横图和竖图需要并列时，按各自宽高比
   分配列宽，使画面高度、图注基线和上下边缘尽量对齐。等宽列会让竖图过高、横图下方
   留出突兀空白。
4. **一组要有明确的外沿。** 两行或四张照片组成一个单元时，先对齐左右外边界，再
   对齐每一行的顶部、底部和图注线。允许内侧错位，但不能让每张照片像独立漂浮在页面上。
5. **无法自然收束时，拆开比硬拼更好。** 山西 06 中，`05–07` 作为一排，`08` 单独
   落在下一段，效果优于为四张不同方向的照片制造一个假想的完整画面。留白可以是节奏，
   但不能是失去关系后的副产品。
6. **单张开场通常放在标题之后。** 除非它被明确设为通栏封面，否则标题、地点与观看
   入口应先出现；不要让一张普通单图意外变成压在标题之前的 hero。
7. **手机保留顺序，不强求缩小版的桌面拼贴。** 先保证组内顺序、编号和阅读方向不变；
   在窄屏把并列组顺次排开，避免把照片缩得过小或为了适配而重排叙事。

### 实作检查清单

- 每个并列组同时检查左、右、上、下边线和图注线；只看单张“好不好看”不够。
- 至少在 375px、768px、1440px 三档检查。桌面端重点看空白是否有意，手机端重点看
  顺序是否保留、照片是否仍能被看清。
- 修改照片、比例或分组之后，以正式构建再看一次；不要只依据编辑画布或旧的本地缓存。
- 若要做可复用预设，优先保存“自然比例并列”“三张比例并列”“三张并列＋下一张单图”
  这类结构，而不是保存某组照片的绝对坐标。

## 建议顺序

下一轮优先重新设计 Room 式总览交互，并请用户用具体参考页面或录屏确认目标产品；
之后实现块间精确落点和可复用预设，再根据真实相册选择 `textImage`、
`masonry` 或 `customGrid`；最后才评估相册级主题。

每加入一种布局，都应使用 375px、768px、1440px 三档视口验证，并检查图片
加载体积、键盘阅读顺序和减少动画设置。
